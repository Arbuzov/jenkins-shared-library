# upsertNoteToMrGitlab

Create or update a single merge-request note identified by a hidden HTML-comment
marker. Re-running the pipeline updates the same note instead of stacking
duplicates (which is what `noteToMrGitlab` does — its `skipIfExist` parameter is
not implemented).

Authentication uses the `PRIVATE-TOKEN` header (the token never appears in URLs
or logs).

## Usage

```groovy
// Warn once per MR, keep the warning current on re-runs
upsertNoteToMrGitlab(
  marker: '<!-- ai-ticket-validation:scenario-check -->',
  comment: "⚠ **No test scenarios found in the Jira ticket.**\n\nPlease add a 'Test scenarios' section.",
)

// Later: flip the same note to a positive message, but only if it exists
upsertNoteToMrGitlab(
  marker: '<!-- ai-ticket-validation:scenario-check -->',
  comment: '✅ **Test scenarios found** — they will be validated after merge.',
  onlyUpdate: true,
)

// Outside an MR build: pass the MR and repo explicitly
upsertNoteToMrGitlab(
  marker: '<!-- my-pipeline:status -->',
  comment: 'Build finished.',
  mrIid: '42',
  gitUrl: 'git@gitlab.asatnet.net:team/project.git',
)
```

Returns the note id, or `null` when `onlyUpdate: true` and no marker note exists.
