# gitlabGetRepositoryTree

Lists the files and directories of a GitLab repository through
`GET /projects/:id/repository/tree`.

The step walks every page of the endpoint, so the tree of a large repository is
returned whole instead of being cut at the API page size. The project is derived
from `env.GIT_URL` by default, which makes the step a one-liner inside a build
of the repository it inspects.

## Usage

```groovy
// The root of the current project, on its default branch
def root = gitlabGetRepositoryTree()
root.each { entry -> echo "${entry.type} ${entry.path}" }

// One directory of a tag, files only
def charts = gitlabGetRepositoryTree(path: 'deploy/charts', ref: 'v1.4.0')
echo "Charts: ${charts.findAll { it.type == 'blob' }*.name.join(', ')}"

// The whole tree of another project, addressed by ID
def tree = gitlabGetRepositoryTree(
  projectId: 412,
  gitlabBaseUrl: 'https://gitlab.example.com',
  ref: 'master',
  recursive: true,
)
echo "Tracked files: ${tree.count { it.type == 'blob' }}"

// Blob SHAs, to compare a fork with its upstream without cloning either
def blobIds = gitlabGetRepositoryTree(recursive: true)
  .findAll { it.type == 'blob' }
  .collectEntries { [(it.path): it.id] }
```

## Parameters

All parameters are optional and passed through a Map:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `path` | repository root | Subdirectory to list, repo-relative |
| `ref` | project default branch | Branch, tag or commit SHA |
| `recursive` | `false` | Descend into subdirectories |
| `gitUrl` | `env.GIT_URL` | SSH or HTTPS repository URL, used to derive the project and the host |
| `projectId` | derived from `gitUrl` | Numeric project ID, or the project path in either spelling — `group/project` is encoded by the step, `group%2Fproject` is passed through |
| `gitlabBaseUrl` | derived from `gitUrl` | GitLab base URL without `/api/v4`. When derived, the scheme and a non-default port of an `http(s)` `gitUrl` are kept; the port of an `ssh://` URL is the SSH daemon's and is dropped |
| `credentialsId` | `'gitlab-text-secret'` | Jenkins credentials ID holding the GitLab token |
| `pageSize` | `100` | Entries requested per API call, 1..100 |
| `maxPages` | `100` | Caps the listing at `pageSize * maxPages` entries, which also bounds the walk at `maxPages + 1` requests |
| `debug` | `false` | Log the request URLs and the response bodies |

## Returns

`List<Map>` — every tree entry in GitLab's own order and shape:

```groovy
[id: '0a1b2c…', name: 'Jenkinsfile', type: 'blob', path: 'Jenkinsfile', mode: '100644']
```

`type` is `blob` for a file and `tree` for a directory. A listing with no entries
comes back as an empty list. A `path` or a `ref` that does not exist in the project
is a different case: GitLab answers `404` and the step fails the build, so an empty
list never stands for "not found".

## Failure behaviour

The step calls `error(...)`, failing the build, when:

- neither `gitUrl` nor `projectId` is available;
- `projectId` is given without `gitUrl` and without `gitlabBaseUrl`;
- `pageSize` is outside 1..100, or `maxPages` is below 1;
- the credentials hold no token;
- the API answers with a status of 400 or above — a missing project, ref or
  path answers `404`, an unauthorised token `401`, and a faulting GitLab `5xx`.
  The message names the request URL and the credentials ID;
- the listing is longer than `pageSize * maxPages` entries. The step refuses to
  return a silently truncated tree; narrow it with `path` or raise `maxPages`.
  A listing of exactly `pageSize * maxPages` entries is returned, not rejected.
